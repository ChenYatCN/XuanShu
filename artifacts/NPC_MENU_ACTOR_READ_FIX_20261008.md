# 多任务菜单 NPC 读取修复（2026-10-08）

## 范围与实现

用户明确授权修复“派克·德拉格 / 深入巴约 / 黄金领域”多任务接取菜单，不是采集搜索切区。
源码确认的等待死角：追踪主线出现在菜单中且目标为拜访 NPC 时，只读取附近 NPCRange 提示；菜单打开后该提示不可见会返回等待，无限时诊断。当前日志没有记录菜单内部 UI 状态，不能断言这就是截图实机唯一触发分支。

- src/questing.py：沿用 NPCServicesWin 的实际可见节点与既有 wndDialogMain 子树，读取 ControlText 中唯一匹配追踪拜访目标的名称。不猜新的 NPC 字段、按钮位置或图标，不把 txtMessage 对话正文或任务选项当作 NPC 身份。
- 优先使用菜单内的已匹配名称；附近提示只作没有匹配菜单名称时的既有回退。多个匹配名称保留歧义，不自动点选。
- HUD 临时不可读时，仅复用交互前已确认的拜访快照：同 Quest ID、Goal ID、区域，位置未偏离 100u，记录不超过已有对话等待上限 60 秒。最终点击前再检查 Goal ID 和 NPC 名称/可见性。
- 当前目标或 NPC 名称读不到时记录原因；持续 5 秒明确警告暂停自动选择，保留列表。数据恢复后继续原流程，而不是自动取消或误接支线。这里限时的是静默等待阶段，暂停后仍允许只读检查恢复。
- 继续复用主线标题匹配、交付/接取确认、所有权、两次未响应点击和累计点击上限；不修改主线任务表。
- 修改仅 src/questing.py、tests/test_npc_mainline_menu.py；保留以前全部未提交工作。
