# 按 X 后十秒倒计时的全组保护

- 用户目标：p3/p4 已判定一起按 X 进入地牢，不允许后续坐标同步把打手拉走。用户明确游戏时序为入口按 X 后在原区域等待 10 秒，之后才出现区域切换画面。
- 日志：附件 053ccacc-12d9-439d-bdff-eb1a5ed28ac2。14:22:09.386 记录 Synchronized dungeon entry: p3, p4；14:22:28.846 p3 从 Mirage/MR_Z00_Hub 切至 Mirage/Interiors/MR_Z00_HideyHole；14:22:39.710 p4 超时未进入。日志没有单次 hitter.teleport 的明细，不能独立证明哪一次坐标传送把 p4 拉出入口。
- 确认的代码缺陷：enter_party_dungeon 的 quest_party_target_sync_active 原来只包住发送 X，发送结束后立即恢复，倒计时和等待加载不再受保护；此时独立跟随可以重新执行坐标/好友传送。加载观察也没有识别已换区域但未采样到短暂加载的成功情况。
- 修改：src/questing.py 中将原有同步暂停延长到全部等待、加载及入场确认结束，在 finally 恢复之前的锁状态，取消和异常也能释放本次锁。增加 quest_party_dungeon_entry_active 标记用于区分入场保护与普通任务移动；没有人为另加固定十秒睡眠，直接观察游戏的倒计时和切区。
- XuanShu.py：入场阶段显示等待全组地牢切区；标记在客户端初始化时清零。原有全组同区域/实例证明及未归队保护保留，入口准备时按原方式对齐位置；按 X 后暂停普通跟随。
- 加载识别：若成员已离开入口区域，不再因为没有观察到 loading=True 而等待额外 15 秒并误报入场失败；最终入场仍要求所有成员同目标区域且同实例。
- 新增四项测试：10 秒源区域倒计时后加载期间两端暂停且没有坐标传送；短加载采样遗漏；倒计时取消释放；跟随循环入场暂停时不读坐标/启动普通跟随。
- 验证：地牢入场、真实 UI 路径、地牢交互、共享目标和跟随共 138 项，136 通过。仍失败的两个旧断言为 warning.assert_called_once() 和 Lemuria 旧组队标记的单人优先级，之前已完成禁用新逻辑的对照；本次不修改其业务逻辑。语法及受影响差异格式检查通过。
