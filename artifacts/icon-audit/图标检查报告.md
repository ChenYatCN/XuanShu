# 玄枢 SVG 图标检查报告

本报告为第一阶段建议，不代表已批准替换。未修改按钮图标引用、原始 SVG、尺寸或颜色逻辑，也未新画图标、打包或运行游戏自动化。

## 1. 检查范围与结论

已核对启动器、快捷键、镜头、开发者工具、状态、飞行路径、脚本、战斗、钓鱼、控制台，以及主窗口标题栏、右侧工具、底部客户端信息、独立弹窗的主要图标定义及调用。当前多数图标不是独立 SVG 文件，而是 Python 中的内联 SVG；下表据实使用“文件／字典键”标识当前图标。

当前顶部十个页签是文字导航，不是十个图标按钮；镜头和开发者工具的右侧多数操作也是文字按钮。本次不为这些位置额外增加图标。

图标库扫描结果：

- `assets/icon/game-icon-pack-v1.4-svg-zh` 共 1,630 个 SVG，包含“间距”和“无间距”两个目录、12 个分类。
- 全部读取 XML，并通过 QSvgRenderer 有效性检查；全部含 `currentColor`。这证明结构可加载，不等于每个图形都适合 UI。
- 从源码提取 87 个字典内联 SVG 制作预览；另人工核对标题栏、钓鱼、生产线与状态战圈等非字典图标。
- 对 62 个候选查看了 16／24／48 像素预览。**未逐个肉眼审阅全部 1,630 张图形**，推荐候选均经过实际形状检查。
- 当前界面以青色细线图标为主，库中候选多为圆润实心图形。优先处理明确语义问题，不建议把清晰的线框图标整套换成实心。

优先级最高：停止符号、自动任务、自动战斗、挂接客户端、最近导入、复制。导入／导出建议作为一对讨论，不只换其中一个。传送阵、自由视角没有无争议的完美候选，列为“可以考虑”。

## 2. 路径约定

下表推荐路径均相对于：

`D:/XuanShuTool/XuanShu-Project/XuanShu/assets/icon/game-icon-pack-v1.4-svg-zh/无间距/`

使用“无间距”只是便于比较轮廓，并非建议将图形撑满按钮。第二阶段仍应设置统一的图形内边距和视觉大小；“间距”版本可作为同形状的留白替代。

“当前内联 SVG”表示保留现有定义，不需要找一个新文件强行替换。

## 4. 多候选取舍

### 自动任务

- A：`2-物品/书.svg`。像任务日志，形状简单，16 像素仍可看出书脊。缺点是单看也可能理解成说明书。
- B：`6-建筑/旗.svg`。目标语义更强，小尺寸清楚；但附近“任务传送”已经是旗帜加目标圈。
- 推荐 **A**，保留“自动任务”文字；不是因为更漂亮，而是减少大脑／AI歧义，同时避免两个任务入口过分相似。

### 自动战斗

- A：`1-游戏/卡牌.svg`。符合 Wizard101 的卡牌战斗，主体比单剑更宽，小尺寸好辨认。
- B：`3-装备/剑.svg`。战斗通用性强，但更像近战，纵向轮廓窄。
- C：`1-游戏/多张卡牌.svg`。强调牌组，但可能误读成牌库／配置，不如 A 直接。
- 推荐 **A**。若更重视跨游戏通用直觉，可选 B；不要把三张图分散用于同一个自动战斗开关。

### 停止自动化

- A：`9-媒体/停止.svg`。圆角实心方块，小尺寸最清楚，语义最明确。
- B：`9-媒体/电源开关.svg`。更像开关软件或断开客户端，不适合“仅停止当前任务”。
- 推荐 **A**；B 不进入优先替换清单。`暂停.svg` 的双竖线只适合真正可恢复的暂停，不能冒充停止。

### 自动对话／接受支线

- 自动对话 A：`9-媒体/消息.svg`，圆润气泡；B：`9-媒体/消息-02.svg`，矩形气泡。
- 推荐自动对话 **A**。两种气泡缩小后太相似，不建议 A、B 分别分配给“自动对话”和“接受支线”。
- 接受支线可用 `9-媒体/书签.svg`；旗帜也是候选，但与任务传送竞争同一语义。书签仅列“可以考虑”，因为它不独立表达“自动接受”。

### 挂接客户端

- A：`9-媒体/链接-02.svg`，水平闭合链节；B：`9-媒体/链接.svg`，斜向链节。

- 未找到同时满足本轮已预览、断开语义明确的配对图；解除挂接暂留现图和明确提示，不拼造断链图。

## 6. 颜色、状态与尺寸约束

1. 当前图标使用 `ctx.stroke_color` 生成 SVG，主题切换通过重建／重新着色渲染。库内 `fill="currentColor"` 不代表放进 QSvgRenderer 后就自动继承按钮颜色；第二阶段必须将当前主题色传给渲染过程，不能原样加载后假设它会变青色。
2. 原始 SVG 保持可着色，不写死青色。预览中的青色只是对比色，不是对原资源的修改。
3. 保留账号异常琥珀色、按钮禁用／选中状态、既有关闭悬停等处理。并非所有当前停止按钮都是红色，不能虚构一套已有危险色规范。
4. 开始与停止优先靠三角／方块区分，再配合现有状态文字；不能仅靠颜色区分。全局主题色变化后仍必须看得懂。
5. 16 像素小图避免复杂纹理；24／32 像素操作图需要与现有线框图做视觉重量比较。库内无间距实心停止方块会显得很大，不能直接铺满原来的 32 像素区域。
6. 当前脚本／钓鱼开始点击区约 44×44、图标 24×24；生产线操作按钮 40×36、图标 24；通用操作按钮约 40×40，部分图标渲染为 32；客户端行和底部信息图更小。第二阶段只在已选图确有需要时调整图形尺寸，保留点击区域。
7. 不改游戏内的站位、学派、友好／敌对等专用标识，也不更换用户自定义软件 ICO。
