# 4.1.5 自动任务基底：游戏对照实测清单

只恢复自动任务及直接流程，保留当前界面、启动器和其他功能。没有游戏内实测。本清单用于同场景对照 4.1.5 和候选，检查实际任务结果。

优先关闭“主线找回”，保持原来的任务端/打手分配。候选文件另起名称，原 EXE 保留。对照时一次只运行一个玄枢实例控制同一组游戏客户端，沿用同一组设置。

| 顺序 | 场景 | 验收结果 |
| --- | --- | --- |
| 1 | 单任务端连续 5～10 个普通任务，包含支线和主线索引外任务 | 按当前追踪目标推进，不因索引失配停住或主动换任务 |
| 2 | 仅自动对话、仅自动任务、两者同时开启，分别普通 NPC 对话 | 按旧版空格/拒绝规则完成，两个流程不互相取消；检查实际 Quest/Goal ID、追踪目标更新 |
| 3 | 接受支线分别关闭/开启；NPC 菜单分别 1 项/多项 | 多任务列表按 4.1.5 点击退出；有拒绝按钮且支线关闭时拒绝，开启时按旧对话接取；检查已接列表，不以点击成功作为验收 |
| 4 | 多任务端各追踪不同任务 | 各自推进目标；不隐式开启主线找回，不因另一个任务端的索引停止 |
| 5 | 普通区域让打手落后、加载、补药，之后归队 | 任务端继续推进；打手按旧距离和好友传送顺序跟随；不同实例不坐标同步 |
| 6 | 普通世界门、跨世界跟随、已有打手世界列表 | 任务端独自交互和选世界；打手不打开列表，已有列表只在空闲且无其他输入占用时关闭 |
| 7 | 组队副本入口、10 秒倒计时、一名打手迟到或进入失败 | 全组同入口/同实例后进入；倒计时不被跟随拉走；逐客户端核对进入目标实例 |
| 8 | 共享机关/房间门，任务端先换房、打手较慢 | 使用旧房间有效记录补跟；新房间坐标不会用于旧房间；缺证据时等待并可手动归队 |
| 9 | 到点未知提示、多楼层、任务点附近障碍、门口没切区 | 近点可见交互窗口、空闲且目标没变时一次受控 X；无窗口不 X；检查正确楼层、最后步行和实际切区 |
| 10 | 移动、对话、倒计时期间停止/重启，任务端换角色 | 停止后无后续输入；旧状态释放；角色和任务缓存重读，不撤销用户停止 |
| 11 | 战后状态残留、失败入战、采集不涨进度、宠物低能量 | 保留对应修复；以真实战斗状态/采集进度验收，低能量只停对应客户端 |
| 12 | 主线找回开启后再关闭 | 只有明确开启才找回；关闭后跟随当前任务；地牢状态不自动转入强制重选主线 |

遇到问题请记录每个任务端和打手的任务/目标、区域、同实例证据、入口标题/提示、加载/战斗/补药状态，以及首次没推进的动作。

需要人工介入的已知边界：真实副本入口或共享房间成员未齐；缺同实例证明；补药后无法确认原副本（只停止失败客户端）；游戏目标/控件不可读。旧队长模式仍保留 4.1.5 的动态队长、队伍等待和重试规则。未接入的 4.2 复合特殊路线可能需要手动完成。

未确认的 NightmareKrok、PowerCore、Castle/OvergrownEstate、Outback 等新版路线未接回普通执行入口；辅助源码仍保留，不把未确认适配当作有效修复。4.1.5 原有路线与现有采集匹配/进度修复保留。
