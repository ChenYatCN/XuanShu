# Lemuria 任务助手导航恢复：源码交付说明

已完成源码修改和针对性验证。按用户最后说明，不打包，由用户自行打包；没有覆盖原有 EXE，也没有接管正在运行的游戏。以下结果不代表游戏内验收。

## 信息读取与检测边界

- 主线身份：复用 `_mainline_identity`，读取当前 QuestID、已拥有的 QuestData、标题 Language Key、主线标记，并调用既有索引匹配；必须成功匹配 Lemuria 主线。不能匹配时不按 END，交给原有主线恢复。
- 目标阶段：读取 GoalID、QuestData.goal_data 对应的 GoalData、目标 Language Key、目标地图及当前 HUD 目标文本。必须是允许任务助手、未禁用导航、非宠物目标的普通对话／探索／使用目标；排除摄影、战斗／采集、小游戏和未知目标类型。
- 目标坐标：读取 `client.quest_position.position()`。坐标必须有限且不是零点，读取异常也作为坐标不可用处理。现有 Hook 在箭头关闭时可能不更新，旧的非零坐标本身不能证明导航正常。
- UI：只读 `WorldView/windowHUD/QuestHelperHud`、其 `ElementWindow/ArrowWindow` 及 `txtDistance`。路径已通过本机游戏 Root.wad 的 `GUI/QuestHelperHud.gui` 核对；未修改游戏资源。

没有一个现成接口能百分之百确认“任务助手故障”。本次使用保守的联合证据：允许导航的普通任务中，HUD 可见，但箭头不可见且没有数字距离，持续同一阶段 **45 秒**，才进入恢复。角色已在有效坐标附近（150 范围内）时跳过，避免将正常到达任务点误判为导航丢失。

UI 控件缺失／不可读时，仅在目标坐标也持续不可用、同一 QuestID／GoalID／目标键／目标地图／目标文本 **300 秒无变化**的情况下采用备用判断。只有无进展、只有 UI 不可读、或有坐标但 UI 状态未知，不会直接触发 END。整个 HUD 隐藏时跳过，不把可能的用户设置当故障修复。任务权限或阶段不可读时也不强行判断。

这些限制意味着部分特殊任务或状态不可读场景会被安全跳过；仍需在真实游戏中验证 UI 可见性与导航状态的对应关系。

## 恢复与成功确认

1. 使用既有 Recovery Lock，所有权为 `lemuria_navigation`。取得锁后再次检查主线、阶段、导航证据和输入安全状态。
2. 保存 QuestID、GoalID、目标键、地图和目标文本，暂停普通任务 TP；再次读到导航恢复则不发送 END。
3. 单次按 END，最多等待 20 秒确认 Loading 或区域切换开始；随后最多等待 35 秒确认到达 **Lemuria/LM_Z00_Hub**，Loading 结束且空闲稳定 1.5 秒。
4. 到达其他地图不算成功。主线／阶段变化时取消原流程；Loading 后短暂的 QuestID=0 或读取失败不作为已完成任务推进。
5. 返回主城后最多检查 30 秒：必须原主线和阶段仍能读取且匹配，箭头可见、数字距离出现、坐标有限且非零，并连续稳定 1.5 秒，才确认导航恢复。
6. 成功后重新启用打手的区域探测、清除组内同步稳定记录，下一轮仍须通过既有主线一致性检查才继续 TP。

单次流程外层有 90 秒上限。每个客户端、每个 QuestID 最多发送 **2 次 END**；次数保存在客户端，Quester 重建不会清零。每次恢复后冷却 **60 秒**。失败时暂停普通任务 TP，冷却期间不重复 END；达到上限后保持等待导航恢复或任务变化，不自动无限回城。稍后自行恢复的导航也须稳定 1.5 秒后放行。停止任务或异常取消均释放锁。

## 安全地图与现有机制协调

END 仅允许在 Lemuria 的八张主地图：Hub、WildLands、UrsaiVillage、NightForest、Badlands、Mandoria、SkyCity、Heap。所有 Interiors、未知地图、已标记的单人区域、组内地牢或地牢恢复区域均排除；不能据世界前缀推断副本可安全离开。现有接口没有可靠的通用实例身份判定，因此不保证覆盖所有未知实例变体；范围明确，宁可跳过。

- 复用既有锁和交互优先级；主线 Finder、NPC 对话、任务链续接、补药、Loading、战斗、区域探测、救援及其他 Recovery 运行时，不并发按 END。
- 特殊地图 TP、近距离触发点恢复和地牢 3 分钟恢复保留原有逻辑，导航恢复不会在它们的地图或活动状态下抢占。
- 对话／切区等待会重置导航确认计时；恢复结束清除该客户端的近点、特殊 TP、NPC 重试和主线观察计时，并刷新既有地牢计时。
- 导航异常观察和恢复等待期间，旧的 120 秒静止重启不会抢先取消整个任务组。
- 各主线客户端独立检测，只对异常客户端按 END；纯打手跳过检测。打手在恢复或失败等待期间先暂停跟随，不因任务端回到主城而错误传送或更新区域探测。
- 组内主线同步门禁把导航恢复等待纳入等待条件；原有全组主线稳定／匹配条件继续生效。传统 leader 模式也逐客户端检查。
