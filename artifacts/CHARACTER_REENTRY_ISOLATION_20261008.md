# 未参与自动化的客户端选角/重进隔离

用户纠正：重新进入角色的客户端不是当前开启自动化的客户端，却影响其他客户端；要求不重启无关客户端。

确认原因：XuanShu.py maintain_client_character_session 在任何已注入客户端返回选角时，都会调用全局 stop_questing_on_client_loss；重进后还无条件调用 _restart_always_on_tasks，取消并重建全体常驻监测任务。之前仅解释“快捷键监听不等于取消注入”，没有覆盖这两处全局影响。

本次修复只修改选角/重进路径：

- 仅该客户端实际启用自动任务或属于尚未完成的自动任务分组时，沿用既有相关任务停止策略；未参与的客户端不触发全局自动任务停止。
- 将本次参与状态保留至清理结束，确保部分状态被清除后失败重试仍完成必要清理。
- 重进只初始化该 Client 对象自己的角色属性、清除旧角色缓存并解除选角门闩，不重建全体常驻监测任务。客户端对象/列表及注入保留，其他客户端的运行任务不取消、不重开。
- 该客户端涉及的脚本、钓鱼与快捷键分组安全暂停仍保留，不自动恢复已停止的自动化。真正关闭/重启进程、手动取消注入等路径未修改。

验证：tests/test_character_session.py 共 11 项测试一次通过，新增检查未参与客户端重进时同伴任务对象保持原样且未取消、待启动任务分组的必要停止及部分清理失败重试。差异空白检查通过。未游戏实测、打包或提交，不能声称实机行为已验证。

改动：XuanShu.py、tests/test_character_session.py、本文档。所有既有任务端优先、采集 90 秒等待等修改保留。
